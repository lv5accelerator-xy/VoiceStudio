# Music workstation integration contracts

These contracts describe the intended P2–P4 additions. P1 endpoints and the UI implement project storage, editable text versions and audio intake.

Shared inputs are the stable `projectId` and `audioAssetId` or `lyricsVersionId`. Each future output receives its own ID, content hash, source IDs, revision, and relative managed path. Capture the input IDs and settings of a job when it is queued. Publish completed output files before recording them in the project. Keep ordinals out of stable references.

| Phase | Proposed operations | Reuse and acceptance boundary |
| --- | --- | --- |
| P2 Separation | `/music/stems` submits a job with `projectId`, `audioAssetId`, and `mode: vocals_background \| four_stems`. Return `jobId`, then typed stem assets with sample rate, channels, sample count, start offset, and hashes. | Extract a shared adapter from the existing Demucs path in `services/dub_pipeline.py`. Reuse process limits and the backend job/event system. Evaluate UVR as an optional provider with separate model, resource and license checks. Reuse the user's installed VoiceStudio environment and require explicit setup for missing weights. Verify timing and sample alignment on Windows, macOS and Linux. |
| P2 Mixing | `/music/mixer` stores `MixerRevision` with stable track IDs, gain in decibels, pan, mute, solo, EQ, compressor settings and source offsets. Produce a waveform envelope and offline WAV render with loudness and true-peak report. | Reuse the shared renderer audio utilities, `ffmpeg_utils`, `dub_mix.py` and the existing loudness measurement. Compare rendered gain, silence and sample count against fixtures. Persist settings separately from source stems. |
| P3 Music video | `/music/mv` stores a schema-versioned `MvTimeline` referencing a mixer render and lyric version. Represent cue, beat and shot ranges in integer milliseconds. Render to either 1920×1080 or 1080×1920 H.264/AAC MP4 using a frozen composition config and stable input hashes. | Review the pinned Remotion instructions and licenses. Add a separately buildable renderer while retaining the existing Electron/Bun locks. Use `karaoke_ass.py` and existing alignment primitives to derive cue and word ranges where appropriate. Support manual video import. An optional, explicitly configured video provider receives only the user-approved scene inputs. Verify fonts, timing, transitions and aspect ratios before enabling render. |
| P4 Workflow | `/music/workflows` extends the existing workflow catalog and runner with stages for lyric/prompt versions, a manual Suno handoff, audio import, stems, mixer render, MV render and export. Checkpoint each completed stage with input/output IDs, settings hash, and job status. | Accept completed manual inputs as stage events. Support cancellation and retries via the existing workflow and job systems. Reuse outputs only when snapshots and hashes match. Record exact tool versions and options for exports. Surface each failure and preserve completed stages. |

Do P2 in a separate change after the P1 platform checks. Begin by verifying that the existing Demucs path can produce a stable two-stem result with already-installed weights and a measured resource budget. Design the four-stem operation and editor controls against that result. Model installation, video providers and actual render integrations need their own review.
